# Blog Core + Audit Fixes — Design (Cycles 1 & 2)

Date: 2026-10-03
Source brief: `blog-build-prompt.md` (full program). This spec covers **Cycles 1 and 2 only**.

## Intent

Keep the portfolio as the credibility layer for recruiters and clients. Add a text blog (first series: System Design, 30 topics) that can be monetised later through a newsletter, then AdSense. This cycle delivers the blog structure, the home page and trust fixes, and the config shape that later cycles plug into. Nothing monetised or third-party ships in this cycle.

## Decisions made with the owner

| Topic | Decision |
|---|---|
| Domain | Stay on `github.io` for now. `siteUrl` is a single config value; switching later is a one-line change. |
| Sequencing | Cycles 1+2 together. Cycle 3 (consent, GA4, Search Console, JSON-LD for posts, OG images, Pagefind) and Cycle 4 (Cloudflare Worker, Resend newsletter, dormant AdSense layer) are separate spec → plan → build rounds. |
| Hero CTA | "View Case Studies" is the single primary button. "Book a Call" and "Download Resume" become secondary text links. |
| Contact | Remove phone and plain-text email. Contact form (placeholder endpoint) + Calendly + LinkedIn. |

## Out of scope (this cycle)

Consent banner, GA4, Search Console tag, Pagefind, generated OG images, Resend/Cloudflare Worker, publish-triggered email, `AdSlot`, `ads.txt` generation, dark mode, and performance tuning beyond the checks listed under Testing. The `site.config.ts` fields for these exist but nothing reads them.

## Starting point (verified in repo)

- Astro 7, Tailwind 4 (`@tailwindcss/vite`), static output, deployed by `.github/workflows/deploy.yml` (push to `main`, `workflow_dispatch`) via `withastro/action@v3`.
- `src/pages/index.astro` (259 lines), `src/pages/404.astro`, `src/layouts/Layout.astro`, `src/styles/global.css` (design tokens: cream `#FAFAF8`, navy accent `#10243E`, IBM Plex Serif / Inter), `src/data/content.ts` (single source of truth for page content).
- `public/` holds `resume.pdf`, `og.png`, `robots.txt`, `sitemap.xml` (hand-written), `llms.txt`, favicons.
- All ten product cards already have Problem / Built / Outcome text. The brief's "four short cards" issue does not apply; no placeholders are added.

## Architecture

### Dependencies added
`@astrojs/mdx`, `@astrojs/sitemap`, `@astrojs/rss`, `reading-time` (or an inline word-count helper), a build-time Mermaid renderer (`rehype-mermaid` with Playwright, or pre-rendered SVG fallback; decided in the plan after a feasibility check on the GitHub Actions runner). Shiki is built into Astro.

### Config
`site.config.ts` at repo root, exporting the shape from the brief §7.1: `siteUrl`, `siteName`, `analytics`, `searchConsole`, `ads`, `newsletter`, `consent`, plus `contact: { formEndpoint: "" }`. All third-party values are empty. `astro.config.mjs` reads `siteUrl` from this file. `person.siteUrl` in `content.ts` is removed in favour of the config value.

### Content collection
`src/content.config.ts` defines the `blog` collection (glob loader on `src/content/blog/**/*.{md,mdx}`, files starting `_` excluded) with a zod schema matching brief §4.1: required `title` (10–70), `description` (80–160), `date`, `tags[]`; optional `updated`, `series`, `seriesOrder`, `level`, `draft` (default false), `canonicalUrl`, `ogImage`, `sources[]`, `email`, `emailSubject`, `emailPreview`. A schema violation fails the build.

Visibility rule, implemented once in `src/lib/posts.ts`: a post is published when `draft === false` and `date <= build time`. Every page, feed and sitemap entry goes through this helper, so drafts and future-dated posts never leak.

### Routes

| Route | Notes |
|---|---|
| `/writing/` and `/writing/page/N/` | 10 per page, tag chips, RSS link |
| `/writing/<slug>/` | Post page |
| `/writing/tags/<tag>/` | `noindex` when fewer than 2 posts |
| `/series/system-design/` | All 30 topics from a curriculum list in `src/data/series.ts`; published ones link, upcoming ones are greyed with no link |
| `/about/`, `/contact/` | New |
| `/privacy/`, `/cookies/`, `/disclaimer/` | Drafts with a visible "Draft — review before publishing" banner |
| `/rss.xml` | Published posts only; summary or full text via config |
| `/sitemap.xml` | Generated by `@astrojs/sitemap`; excludes `noindex` pages. The hand-written `public/sitemap.xml` is deleted. |
| `/404` | Existing page gains latest posts and a subscribe fallback |

Trailing-slash policy: `always`. Existing anchors `#products`, `#skills`, `#experience`, `#faq` keep working.

### Components (`src/components/`)
`PostLayout` (in `src/layouts/`), `TOC` (H2/H3, collapsible on mobile, current-section highlight via IntersectionObserver), `Callout` (variants Note, Tradeoff, FromTheField, WhenNotToUse, Pitfall), `SeriesNav` ("Part N of 30", prev/next, hub link), `RelatedPosts` (shared tags, max 3), `AuthorBox` (bio, About/LinkedIn/GitHub links, employer disclaimer), `PostCard`, `Sources` (renders `sources` frontmatter), `ShareLinks` (plain links: LinkedIn, X, copy-link), `Subscribe` (stub: shows "Follow via RSS / LinkedIn" fallback, driven by `newsletter.provider`), `Footer`, `ContactForm`.

Client JS on post pages is limited to: TOC highlight, copy-code button, copy-link, mobile nav (existing). No third-party requests.

### Post page behaviour
Max line length ~70ch, styled code blocks with build-time Shiki highlighting and a copy button, responsive tables, heading anchors, print stylesheet, reading time, published and "Updated" dates, tag chips, level badge. Mermaid diagrams render to inline SVG at build time; images require alt text. Comments off. Subscribe fallback box after the intro and at the end of each post. `BlogPosting` JSON-LD is deferred to Cycle 3; this cycle emits correct `<title>`, description, canonical, Open Graph and Twitter tags per post (using the default `og.png` until Cycle 3 generates per-post images).

### Authoring workflow
- `src/content/blog/_template.mdx`: the 11-section skeleton from brief §4.4 with the editorial HTML comment.
- `npm run new-post "Title"` (`scripts/new-post.mjs`): creates a dated `draft: true` file from the template with a slugified filename; refuses to overwrite.
- `src/content/blog/rate-limiting.mdx`: sample, `draft: true`, clearly marked placeholder text, no invented statistics. Its job is to prove the pipeline.
- Deploy workflow gains `schedule: cron "30 0 * * *"` so future-dated posts publish on their day.
- `README.md`: add a post, schedule a post, preview locally, deploy; marks Cycle 3/4 features as "not yet built".
- `CHANGELOG.md`: one entry per cycle.

## Home page and audit changes (Cycle 2)

1. **Hero CTA:** primary = "View Case Studies"; Book a Call and Resume rendered as text links. Profile-card "Blog ↗" now points to `/writing/` (internal link, no `target=_blank`); `person.blog` bit.ly is removed.
2. **Nav:** "AEO / FAQ" → "FAQ"; add "Writing" → `/writing/`. Section tag "AEO — Answer Engine Optimization" → plain label. Mobile nav still works.
3. **Latest writing strip:** 3 newest published posts plus a link to the series hub; renders nothing when there are no published posts (true at launch).
4. **Subscribe fallback box** above the footer on the home page.
5. **Footer:** remove `tel:` and `mailto:` links. Show Contact, LinkedIn, Calendly, Privacy, Cookies, Disclaimer, the line "Views expressed here are my own and do not represent my employer.", and a "Last updated" date from the build date.
6. **Personal data:** delete `person.phone` and `person.email` from the rendered page. Remove `email` and `telephone` from the `Person` JSON-LD in `Layout.astro`. Proposed FAQ replacement for the contact answer (owner to confirm before applying): *"The quickest way is to book a 30-minute call on Calendly or send a message through the contact page. Kumar is also on LinkedIn and GitHub."*
7. **Contact page:** form posts to `contact.formEndpoint`. When empty, the form is replaced by Calendly and LinkedIn links, so there is never a broken form.
8. **FAQ:** 3–4 new questions on system design, real-time data architecture and CDP, drafted only from facts already on the page and shown to the owner before merging. Existing `FAQPage` JSON-LD picks them up automatically.
9. **About page:** short bio; photo slot that falls back to the "KA" initials when no photo file is supplied. Testimonials and "featured in" strips render only when items exist in `content.ts`.
10. **Legal drafts:** `/privacy/` already describes analytics, ads and newsletter data handling (email, signup time, source; Resend and Cloudflare as processors; retention; deletion requests) so it does not need rewriting in Cycles 3–4. `/cookies/` explains the planned consent categories and states that no cookies are set today. `/disclaimer/` carries the employer disclaimer and an educational-content notice.
11. **Verification pass:** heading order, muted-text contrast, focus styles, alt text, image dimensions, font loading, `resume.pdf` size and name, `og.png` is 1200×630. Findings beyond the list are reported, not silently fixed if they change visible design.

**Untouched:** every metric, client name, award and claim in `content.ts`. A checklist for the owner covers: team size and tenure vs LinkedIn/resume, revenue and ARR figures, named client brands, "reports to CEO", internal stack details, and "Atlantis/Logra" naming consistency.

## Data flow

`content.ts` and `series.ts` feed the home and series pages. The `blog` collection → `posts.ts` (visibility + sort + related) → index, tag, series, post, RSS, sitemap, and home strip. `site.config.ts` → `astro.config.mjs`, `Layout.astro`, `Subscribe`, `ContactForm`, footer.

## Error handling

- Invalid frontmatter: build fails with the zod message naming the file.
- Missing `formEndpoint` or `newsletter.provider = "none"`: graceful fallback UI, never an empty or broken form.
- Zero published posts: strip hidden; `/writing/` shows an "first posts coming soon" state with the RSS link; series hub shows all topics as upcoming.
- Mermaid render failure: build fails loudly (no silently missing diagrams).

## Testing and acceptance

Automated where cheap: a `scripts/` check run in CI that builds and asserts no `tel:`/`mailto:`/phone string in `dist/`, no third-party hostnames in built HTML (only Calendly/LinkedIn/GitHub outbound links), the draft sample post is absent from `dist/`, sitemap contains no draft or noindex URLs, and `rss.xml` parses. Manual: add a temporary published post and a future-dated post to confirm page, index entry, tag page, RSS item, sitemap entry appear (and the future one does not); keyboard walk-through of nav, TOC and copy button; Lighthouse mobile on `/`, `/writing/`, and a post, recorded before and after (target ≥ 95 in each category, LCP < 2.5s, CLS < 0.1); 320px width check with no horizontal scroll.

Acceptance (from the brief's 18 criteria, those in scope): 1, 2, 3, 4 (zero third-party requests, no cookies), 7 (vacuously true, no ads), 9, 10 (no consent banner or search yet; TOC and nav only), 11, 12, 17 (fallback UI), 18.

## Risks and open items for the plan

- Build-time Mermaid needs a headless browser in CI. The plan starts with a feasibility spike; fallback is pre-rendered SVG committed alongside posts.
- Astro 7 and current integration versions should be confirmed against their docs during planning rather than assumed.
- `github.io` has no root `ads.txt` and cannot send verified email, so Cycle 4 is test-mode only until a domain exists.
- Final legal wording needs the owner's (ideally a lawyer's) review before launch.
